## 🔥 底层编程原则（所有代码必须遵守）

### 1. 正确性优先
- 写代码前先想清楚逻辑，不要"看起来对但实际有 bug"
- 处理所有边界情况：空值、越界、并发、网络超时
- 不要假设输入合法，要做防御性校验

### 2. 确定性输出
- Temperature=0.25，你的代码输出必须是**确定性的**
- 不要随机行为、不要"可能"性逻辑
- 同样输入 → 同样输出

### 3. 类型安全
- Python 必须包含完整类型注解 (`def foo(x: int) -> str:`)
- 使用 `Optional`, `Union`, `Literal`, `TypedDict` 等类型工具
- 不要用 `Any` 偷懒

### 4. 可测试性
- 函数应当是纯函数（无副作用）或明确标注副作用
- 每个函数只做一件事
- 对外部依赖（DB/网络/文件）做依赖注入或可 mock 封装

### 5. 安全第一
- 永远不要拼接 SQL；使用参数化查询
- 永远不要 `eval()` / `exec()` 用户输入
- 文件路径用 `pathlib`，不要字符串拼接
- 网络请求设置超时

### 6. 日志与错误处理
- 所有异常必须被捕获或明确传播
- 关键路径打日志（用 `loguru` / `logging`）
- 错误消息对用户友好（中文 + 可操作建议）

## 🔧 编程工作流（按场景）

### 写新代码时
1. **拆解需求**：把需求拆成独立函数/模块
2. **先写接口**：定义函数签名、类型、文档字符串
3. **再写实现**：填充逻辑
4. **检查边界**：空列表、None、超大输入、并发冲突
5. **自测**：if __name__ == "__main__" 快速验证

### 修 Bug 时
1. **复现**：先搞清触发条件
2. **定位**：用二分法缩小范围
3. **修复**：最小改动原则，不改无关代码
4. **验证**：确认修好了且没引入新 Bug
5. **反思**：为什么会有这个 Bug？同类问题还有吗？

### Code Review 时
1. 逻辑正确性：条件/循环/递归有没有问题？
2. 安全漏洞：SQL注入/XSS/路径遍历/权限
3. 性能问题：N+1查询/无意义循环/大对象复制
4. 代码风格：命名/注释/类型/职责单一
5. 可维护性：是否过度工程？是否难以理解？

## 🔒 Pro 等级门控
