三、核心发现

P0 — 正版 PRO 用户的自改进能力不工作

这是当前最大的真实风险：付费用户付了钱，但拿不到他们唯一买的东西。

strings.py 发布版 public_key = ""     ← 空占位符
    ↓
verify_license() 永远抛 LicenseInvalid
    ↓
can_modify_self() 永远返回 False      ← 自改进入口
    ↓
正版 PRO 用户登录成功后也无法触发自改进

涉及文件： - tools/encrypt_strings.py → 未被用于生成公钥密文 - src/security/strings.py:38 → _STORE["public_key"] = "" 仍为占位符 - src/security/safe_modify.py:255-267 → can_modify_self() 因验签失败永远返回 False - src/ui/pro_status_widget.py:172-185 → 验签失败被 pass 绕过，UI 显示不反映真实授权状态

修复目标：让付费 PRO 用户的自改进能正常工作。

✅ 已修复 — 试用机制从本地文件迁移到服务端计次

这是 v2→v3 最大的改动。旧的试用设计存在致命漏洞：

// 旧（已移除）
trial.dat → XOR 加密存本地 → 删文件 = 无限试用

新设计：

// 新（服务端计次）
用户注册 → 登录 → JWT 含 trial_ai_count: 3
    ↓
无 Key 时 model_manager 检出 trial_ai_count → 走 trial.php 代理
    ↓
trial.php 验 JWT → DB 查 trial_ai_count → 代理 DeepSeek → UPDATE 扣 1
    ↓
3 次用完 → 402 → 提示填 Key 或升级 PRO

涉及改动的文件：

  • 服务端：api/auth/login.php（JWT 含 trial_ai_count）、api/ai/trial.php（AI 代理 + 计次扣减）、database/migration.sql（ll_useregs 加 trial_ai_count 列）、config/database.php（DEEPSEEK_API_KEY）
  • 客户端：login_dialog.py（删跳过试用按钮）、trial_store.py（改读 JWT）、token_store.py（加 trial_ai_count 字段）、auth_client.py（加 trial_call()）、model_manager.py（试用用户路由到 trial.php）、strings.py（加 api_trial 端点）

防羊毛手段：trial_ai_count 存 MySQL 删不掉；DB 级 WHERE trial_ai_count > 0 防并发扣超；服务端不信任 JWT 中的值，每次从 DB 重新读。

P1-1 代码保护缺失 → 被篡改二次分发的风险

  • Cython 编译（setup_cython.py）从未进入发布构建，9 个 security 模块全部以 .pyc 形式随 exe 发布
  • UPX 一层可以 upx -d 直接脱掉
  • 无代码签名（codesign_identity=None）
  • startup_self_check() 在 frozen 模式下跳过所有实质性检查

威胁：有人解包→插入代码→重新发布，打着"7Tan 免费版"的旗号传播后门/挖矿/勒索软件。

P1-2 本地 API 安全隐患

src/web/server.py → FastAPI 127.0.0.1:9800，本地请求免鉴权，含 api_terminal.py（subprocess.Popen 任意命令执行）。
